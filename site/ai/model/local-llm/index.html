How this ranking works

This page ranks open-weight LLMs people run locally (Llama, Qwen, Gemma, Phi-4, Mistral Small, DeepSeek-R1 distills and more). Unlike the other BigRank boards there are no public usage APIs for model downloads, so every number here is hand-maintained from the official model cards in config/local-llm.json. The daily collector snapshots which models are tracked into data/local-llm_snapshots/, so the tracked list is auditable over time.

Capability score

Each benchmark is min-max normalized across tracked models to 0–100, then combined with adjustable weights (defaults: MMLU 45%, HumanEval 35%, context length 20%). Drag the sliders to re-weight — the ranking recomputes instantly in your browser.

Hardware filter

  • Min RAM / Min VRAM are rough minimums for running the model at Q4-class GGUF quantization with acceptable quality. They are approximations, not measured floors.
  • Min VRAM 0 means the model is practical on CPU alone (small models).
  • Pick your machine's budget in the two dropdowns; the table shows only models that fit. Both filters combine (AND).

Quant formats

The Quants column lists the compressed builds a model is commonly served in (GGUF format, used by Ollama, llama.cpp and Hugging Face). Models are trained at 16-bit precision; quantization re-stores the weights at lower precision so they fit in consumer RAM/VRAM — roughly 2–8× less memory for a small quality cost:

  • Q4_K_M ~4-bit — the standard size/quality trade-off and the most downloaded variant.
  • Q5_K_M / Q6_K ~5/6-bit — slightly better quality, larger files.
  • Q8_0 ~8-bit — near-lossless.
  • FP16 full 16-bit precision — no compression.

Rule of thumb: download size ≈ parameter count × ~0.55 GB per billion parameters at Q4 (a 70B model ≈ 40 GB). The board's Min RAM / Min VRAM figures assume Q4-class quants; higher-precision quants need proportionally more memory.

Benchmark freshness

🟢 Fresh = benchmarks updated within 90 days of the latest snapshot, 🟡 Aging = 90–180 days, 🔴 Stale = older. Hover a badge for the exact date. Update last_benchmark_update whenever you refresh a model's numbers.

Caveats

  • Benchmark values are single published/approximate figures, not independent evaluations — treat ranks as indicative, not authoritative.
  • MMLU/HumanEval are not directly comparable across chat vs reasoning-tuned models; a reasoning model's score often assumes long chain-of-thought.
  • Context length is the native window (YaRN-extended maximums noted in model cards may be higher at some quality cost).
  • Benchmark sources vary by generation: older rows report classic MMLU/HumanEval, while 2026-era rows report the closest published equivalents (MMMLU/MMLU-Pro/MMLU-Redux for knowledge, LiveCodeBench v6 for coding). Hover a benchmark cell for the exact source.
  • This board is maintained by hand — to add or correct a model, edit config/local-llm.json and open a pull request.
